# 本地化执行说明

本说明文档用于指导 AI Agent（或人工协作者）为任意 Flutter 项目生成、扩展与校验本地化 `.arb` 文件，确保多语言质量、命名规范与交付一致性。对其他技术栈亦可借鉴相同思路，只需调整产物格式与工具命令。

---

## 1. 目标与适用场景

- 快速复制到新项目，要求 AI Agent 依据本指南生成或更新多语言翻译。
- 支持以 `intl_xx.arb` 命名的 Flutter Intl 方案，也可扩展到 JSON、CSV 等格式。
- 适合以下场景：
  - 初次搭建国际化方案，批量生成目标语言文件。
  - 既有项目新增文案或新增目标市场。
  - 定期复查翻译一致性、占位符与复数规则。

## 2. 目录与文件命名

- 默认结构：
  - `lib/arb/intl_en.arb`：基准语言（常用英文）。
  - `lib/arb/intl_xx.arb`：各语言翻译文件，`xx` 使用 BCP-47 语言代码。
  - `lib/l10n/l10n.dart`：Flutter Intl 自动生成的本地化入口。
- 如果项目使用不同目录（如 `assets/i18n`），需在执行任务前明确告知 AI Agent。

   - 特殊术语表（术语映射、缩写说明）。

### 3.2 输出要求

- 每个目标语言生成独立 `.arb`。
- 保持 key 顺序与基准语言一致，方便 diff。
- 文件需通过 `flutter gen-l10n` 或 `intl_utils` 编译校验。

## 4. 执行流程（AI Agent 操作步骤）

1. **同步基准文件**：读取最新 `intl_en.arb`（或指定基准）。
2. **比对差异**：如有旧版本，先 diff，识别新增/变更 key。
3. **生成翻译**：
   - 优先利用术语表与上下文。
   - 保留 `{placeholders}`、`@` 元数据、`select`/`plural` 结构。
4. **自动校验**：
   - 检查 JSON 结构与编码（UTF-8）。
   - 占位符数量与名称需与基准一致。
5. **人工或二次审校（可选）**：确认语气、单位、货币符号等。
6. **生成总结**：列出新增 key、缺失语言或待人工确认的条目。

## 5. ARB 写作规范

- **Key 命名**：lowerCamelCase，语义清晰，如 `homeTitle`、`errorNetwork`。
- **占位符**：
  - `{count}`、`{userName}` 等必须在 `@key` 中声明 `placeholders` 的 `description` 与 `type`。
  - 翻译内容不得新增或删除占位符，顺序保持一致。
- **复数与条件**：使用 ICU 语法，例如：

```json
"itemsCount": "{count, plural, =0 {暂无数据} other {共有 {count} 条记录}}",
"@itemsCount": {
  "description": "列表数量提示",
  "placeholders": {
    "count": {
      "type": "int",
      "format": "decimal"
    }
  }
}
```

- **文案风格**：遵循《中文文案排版规范》及目标语言本地惯例，保持正式、简洁。
- **特殊字符**：必要时使用转义，避免硬 Tab、行尾空格或未闭合的引号。

## 6. 交付校验清单

- ✅ 所有目标语言文件均存在且可解析。
- ✅ Key、占位符、`@` 元数据与基准一致。
- ✅ 表情符号、HTML、Markdown 片段被正确转义或保留。
- ✅ 本地化单位、货币、日期格式符合目标市场习惯。
- ✅ `flutter gen-l10n` 或 `flutter pub run intl_utils:generate` 能顺利通过。

## 7. 推荐任务提示模板

可直接复制以下模板，在其他项目中向 AI Agent 下达需求：

```text
你是负责本地化的 AI Agent。
请基于 <项目路径>/lib/arb/intl_en.arb 生成以下语言的翻译文件：
[在此列出语言代码，如 en, zh, ja, fr...]
要求：
1. 保留所有 key、占位符与元数据结构；
2. 翻译需遵循正式语气，必要时参考术语表（若提供）；
3. 输出为 UTF-8 编码的 intl_xx.arb 文件，放入 lib/arb/；
4. 返回总结，说明新增/更新的 key 和需要人工确认的条目。
```

根据项目实际情况，可追加诸如“使用英式拼写”“保留品牌名不翻译”等特殊要求。

## 8. 维护策略

1. **版本控制**：每次翻译发布建立独立分支或变更集，方便审阅与回滚。
2. **周期复查**：建议每季度检查一次语言文件，确保新功能文本已同步。
3. **数据驱动**：结合各语言活跃用户或营收占比，动态调整语言优先级。
4. **人机协同**：AI 先产出初稿，再由人工校对，可平衡效率与质量。
